## 4. Styling system

**Tailwind CSS v4** (installed 4.3.0) via `@tailwindcss/postcss`. Plain global CSS lives in `app/globals.css`. There are no CSS modules, styled-components or CSS-in-JS. `clsx` + `tailwind-merge` are wrapped in a local `cn()` helper that is copied into 6 files.

### Configuration: what's actually active

- **Active:** the `@theme { … }` block in `app/globals.css:3-33`.
- **Inactive:** `tailwind.config.ts`. Tailwind v4 only reads a JS config if CSS has `@config`, and `globals.css` has none. The file duplicates the colours/fonts/keyframes but has no effect.
- `@theme` defines `--font-family-sans` / `--font-family-mono`. These are **not** v4 theme keys (v4 uses `--font-sans` / `--font-mono`), so they do nothing. Fonts still render correctly by accident (see Fonts).
- `:root { --background … --foreground }` (`globals.css:36-44`) is never referenced.

**Dark mode:** dark only. No `prefers-color-scheme`, no `dark:` variants, no toggle.

### Fonts and how they load

- `next/font/google` in `app/layout.tsx:9-10` loads **Inter** (`variable: "--font-inter"`) and **JetBrains Mono** (`variable: "--font-mono"`).
- They are self-hosted woff2 variable fonts (Inter 100–900, JetBrains Mono 100–800) with `font-display: swap`. The latin subset is requested, but the output also contains other Inter subsets.
- **Inter** reaches the page only through the plain CSS rule `body { font-family: "Inter", sans-serif }`. The `font-sans` class on `<body>` resolves to Tailwind's default system stack and loses to that rule. `--font-inter` is never used.
- **JetBrains Mono** works because the next/font variable is named `--font-mono`, which overrides Tailwind's own `--font-mono` theme variable.
- Usage: Inter for all body and headings. JetBrains Mono for the logo, eyebrows, tags, metrics, stats, form labels, footer headings and the code card.
